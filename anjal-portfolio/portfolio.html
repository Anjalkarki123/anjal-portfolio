Portfolio

Three projects, and what I learned from checking each one carefully.

Internal invoicing web application

React · FastAPI · OAuth 2.0 · 2026 internship, RCDS / IIDS

The billing team needed a faster way to produce invoices. I built a web application with a React front end and a FastAPI back end, then tested and debugged it across the front end, the API layer, and a third-party integration that failed intermittently.

What I caught: AI-generated invoice data could look correct and still be wrong, so I designed a review step where a person checks every invoice against the source data before it's released.

I gathered requirements directly from billing staff and validated each feature against them before release. Sign-in uses university single sign-on with OAuth 2.0, so the app never stores a separate password.

Multi-class diabetes classification

Python · scikit-learn · pandas · NumPy · May 2026

I trained and evaluated four classifiers on 253,680 CDC health records with 21 features. Stratified splits and a fixed random seed made every run reproducible, so results could be compared fairly.

What I caught: the two highest-scoring models reached 84.9% accuracy but never detected the rarest class. They looked good only because they always guessed the most common answer.

I replaced accuracy with per-class recall and macro-F1 as the pass criteria, corrected the imbalance with class weighting, and documented the full method in an IEEE-format report.

Lost Map Studio: 2D game

C# · WPF · November 2025

A 2D game built in C# with WPF. I wrote the enemy AI as a state machine so each behavior (patrol, chase, attack) could be tested on its own instead of only through full play-throughs.

What I caught: an intermittent frame stutter. I profiled the update loop to isolate the cause rather than guessing.

I also built a self-playing demo mode that runs the same input sequence every time. It works as a regression test: if a later update changes behavior, the replay shows it immediately.
